X2Cscope Library Binary Support Matrix
=======================================

Summary
-------
Use libx2cscope-generic-32dsp-dspic33a-elf.a or
libx2cscope-generic-32dsp-dspic33a-mlarge-elf.a for dsPIC33AK devices.
The combined libx2cscope2-generic-pic24-dspic33-elf.a archive is intended
for the non-MLarge 16-bit XC-DSC families; it is not a validated
multi-architecture library for dsPIC33AK.

The processor options below are taken from the corresponding *.mk build
files. XC-DSC targets use -mcpu=; XC32 PIC32M targets use -mprocessor=.
The Cortex-M targets are generic: they call XC32's ARM compiler (pic32c-gcc)
with core options only, without -mprocessor and without a device pack.

Cortex-M: which library for which device
----------------------------------------
Pick the library by core and FPU of the device (see the device data sheet
or the Dcore/Dfpu entries of its device pack):

  Core / FPU                     Library                    Example families
  -----------------------------  -------------------------  ---------------------------------
  Cortex-M0+, no FPU             libx2cscope2-cm0-elf.a     SAM D/C/L/R, PIC32CM PL/JH/MC/GV
  Cortex-M23, no FPU             libx2cscope2-cm0-elf.a     PIC32CM LE/LS/GC00/SG00, SAML10/11
  Cortex-M4,  no FPU             libx2cscope2-cm0-elf.a     PIC32CX-SG
  Cortex-M4,  SP FPU (M4F)       libx2cscope2-cm4-elf.a     SAME5x, SAMD51, SAMG, PIC32CX BZ/MT/SG4x/SG6x
  Cortex-M7,  DP FPU             libx2cscope2-cm7-elf.a     SAME70, SAMS70, SAMV7x, SAMRH7x, PIC32CZ CA/MC
  Cortex-M33, SP FPU + DSP       libx2cscope2-cm33-elf.a    PIC32CK SG/GC

The application must use the same float ABI as the library: soft-float for
cm0, hard-float for cm4/cm7/cm33 (XC32 default for devices with FPU). A
mismatch is reported by the linker ("uses VFP register arguments").
Exception: libx2cscope2-cm7-elf.a also links into Cortex-M4F and Cortex-M33
projects, but uses double-precision FPU instructions that these cores do not
have; it faults at runtime (scope trigger on a double channel). Never use
the cm7 library on a device without a double-precision FPU.

Notes
-----
1. Generic binaries target an architecture/family, not necessarily every
   device revision. The application must use a compatible compiler, linker
   configuration, device headers, and memory model.
2. The -mlarge binaries are not interchangeable with the normal variants.
3. The combine step also collects normal dsPIC33AK objects because that
   target uses the shared XC-DSC object directory. However, this produces a
   mixed-architecture archive and should not be considered a validated
   dsPIC33AK library. Use the dedicated dsPIC33AK archive instead.
4. The Cortex makefiles define __GENERIC_MICROCHIP_PIC32__ for X2Cscope
   device-info reporting. Therefore, the Cortex binaries are ARM-compatible,
   while their reported device-info family may identify as PIC32.
5. The generic Cortex binaries produce the same code as the former
   device-specific builds (ATSAMD21G18A, ATSAME54N20A, ATSAME70N20B,
   PIC32CK2051SG01064) with XC32 v4.60. They were link-tested with
   ATSAMD21G18A, PIC32CM6408PL10048, PIC32CM5164LE00048, ATSAME54N20A,
   ATSAME70N20B, ATSAMV71Q21B and PIC32CK2051SG01064 projects.
